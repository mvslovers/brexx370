Dialog with the reworked ZP60038 in the LPA, TK5, 2026-11-06.
The reworked IKJCT441 (package zp60038.zip, sha256 d0120eaf75f992a17629b6c7bcb428b8ad5376672df8a4e225cea01bd655b626) was installed
with the $INSTALL of the package on a throwaway TK5 whose library USERMOD.ZP60038 had been replaced with the members of the
package (case 1b of results-zp60038-install.txt: jobs 44 and 45, IKJCT441 2728 bytes, id IKJCT441 ZP60038 20261103 in
SYS1.LPALIB(IKJPTGT)). The system was then shut down and IPLed again; the TK5 image has CLPA in IEASYS00 (the usermod's
README says so; IEASYS00 was not read in this container, and the module in storage was not dumped). BREXX/370 3.1.0 (tag
v3.1.0, 5aabe49) was deployed under its own name, ZMG0001 of that release installed (ZMG0001.xmit, sha256
d3a0ed8f0c18cbfea6b9bf59a27485e1eb837d8b613cc0172a185020bda7bc64; backup job 49, apply job 51).
Harness: the ISPF scripts of the ZMG0003 usermod (after.sh, twoscreens.sh, attention.sh) with the private IKJCT441 deleted
(ZMG_LPA=1), so ISPF loads IKJCT441 from the LPA. Setup and ZMGWHO jobs, all RC 0000: JOB00052 and JOB00053 (after.sh),
JOB00054 and JOB00055 (twoscreens.sh), JOB00056 and JOB00057 (attention.sh).
Order below: twoscreens A C D E, then the after.sh cases, then attention. Screens as the harness read them (the harness'
own log lines are left out). WH2 is the second line of ZMGWHO: U ECTUSER, R variable routine, W ENVBLOCK+X'130' X'134'
X'138' X'13C', M largest piece of subpool 1. E is ECT+X'30' (ECTENVBK).

Compared with results-after.txt, which was measured with the same exec set and the ZMG0003 module as a private IKJCT441
(BREXX/370 9dbcf46). Addresses (any 8 hex digits) masked; RCs, values and order compared line by line.
  A, D, E              identical. (The reference A, C, D, E has no WH2 line; ZMGWHO had none then. Ignoring WH2: 0 differences.)
  C                    identical in values and order; two screen lines differ in how the harness caught a line: a "***" line
                       followed by "Place cursor on choice and press ENTER to Retrieve Command" in the reference, a single line
                       "*** ace cursor on choice and press ENTER to Retrieve Command" here (80 lines against 78). The command
                       panel text is the same; no value is involved.
  CR, REXXREXX, REXXCLIST, NESTCTL, REOPEN, MEMORY
                       identical (58, 74, 66, 331, 55, 86 lines); no difference after masking.
  CLISTREXX, ATDISPLAY the same values and RCs, plus extra screens at the end of the run: two more snapshots of the TSO command
                       panel after the exec ended (XN4-2, XN4-3 and XC-2, XC-3), and in CLISTREXX the status line of the last
                       screen reads "CommSA and Controls Refreshed" where the reference has "TSO Command Executed ISPEXEC
                       SELECT CMD(%XN4) (10)". The number of snapshots depends on timing; no VPUT, VGET or DISPLAY line moved.
  ATTENTION READY, ISPF identical to the sections of the same name in results-after.txt (WH2 included).
